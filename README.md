# FitFindr — Project 2

---

## About

FitFindr is a stateful, multi-tool AI agent that helps users thrift clothes and figure out how to style them. It takes a natural language request, searches a mock secondhand dataset, evaluates the best match against the user's existing wardrobe, and generates a highly shareable outfit caption.
---

## Tool Inventory

The agent orchestrates three distinct tools. Each tool is designed to fail gracefully and return specific data types.

### 1. `search_listings`
* **Purpose:** Searches the mock dataset for items matching the user's keyword, size, and price constraints. Uses a keyword overlap scoring mechanism.
* **Inputs:** * `description (str)`: Keywords to search for.
  * `size (str | None)`: Exact size to filter by (case-insensitive substring match).
  * `max_price (float | None)`: Maximum price limit.
* **Outputs:** `list[dict]` - A sorted list of listing dictionaries (highest score first). Returns an empty list `[]` if no matches are found.

### 2. `suggest_outfit`
* **Purpose:** Uses the Groq LLM (`llama-3.3-70b-versatile`) to generate styling advice by pairing the newly thrifted item with specific pieces from the user's existing wardrobe.
* **Inputs:** * `new_item (dict)`: The single listing dictionary selected by the search tool.
  * `wardrobe (dict)`: The user's wardrobe object, containing an array of existing clothing items.
* **Outputs:** `str` - 1-2 paragraphs of styling advice.

### 3. `create_fit_card`
* **Purpose:** Condenses the outfit styling advice into a short, authentic social media caption (e.g., for Instagram or TikTok) using the Groq LLM.
* **Inputs:**
  * `outfit (str)`: The paragraph generated by `suggest_outfit`.
  * `new_item (dict)`: The selected listing dictionary (used to extract price and platform for the caption).
* **Outputs:** `str` - A 2-4 sentence punchy social media caption.

---

## Planning Loop & Conditional Logic

The agent (`agent.py`) uses a sequential execution loop with a critical conditional branch:
1. **Parse & Execute:** Extracts size/price constraints via regex, cleans the keyword description, and executes `search_listings`.
2. **Conditional Check:** The agent checks the returned results. 
   * **If results are empty (`[]`)**: The loop sets a specific error message in the session state and **returns early**, halting execution immediately so it doesn't waste LLM calls on non-existent items.
   * **If results are found**: It grabs the top result (`results[0]`) and proceeds.
3. **Execute Generative Tools:** It calls `suggest_outfit` unconditionally using the top item, then passes that output into `create_fit_card`.

---

## State Management

Information flows between the tools via a centralized `session` dictionary initialized at the start of `run_agent()`. 
* **What is stored:** The original query, parsed parameters, raw search results, the `selected_item`, the `outfit_suggestion`, the `fit_card`, and an `error` string.
* **How it is passed:** The loop never asks the user for information twice. The `selected_item` dict returned by the search tool is stored in `session["selected_item"]` and directly passed as an argument into `suggest_outfit`. The string returned by `suggest_outfit` is stored in `session["outfit_suggestion"]` and directly passed into `create_fit_card`.

## Error Handling Strategy

Each tool was built with isolated Test-Driven Development (TDD) using `pytest` to ensure it fails gracefully without crashing the application.

1. **`search_listings` (Zero Results):** Deliberately searching for impossible items (e.g., `designer ballgown size XXS under $5`) returns an empty list instead of throwing an exception. The planning loop catches this and informs the user: *"No matching listings found. Try adjusting your size or price constraints."*
2. **`suggest_outfit` (Empty Wardrobe):** If a new user searches with the "Empty wardrobe" toggle, the tool catches the empty `wardrobe['items']` array. Instead of breaking, it uses a fallback LLM prompt to offer *general* styling advice based on the item's style tags.
3. **`create_fit_card` (Missing Outfit):** If the input outfit string is empty or just whitespace, a guard clause intercepts it and returns a hardcoded error string (`"Error: Could not generate a fit card because the outfit suggestion is missing."`) rather than failing the LLM call.

## Spec Reflection

* **How the spec helped:** Writing out strict tool contracts and failure modes in `planning.md` made implementation incredibly smooth. It allowed me to use `pytest` to verify the isolation of each tool before ever wiring up the complex agent state, preventing cascading bugs.
* **Where implementation diverged:** 1. I diverged from asking the LLM to parse the user's input query. Instead, I used a lightweight Regex implementation (`re`) in `agent.py` to extract price and size parameters. This was faster, cheaper, and more reliable than an LLM parser. 
  2. While building the search tool, I realized my simple substring match had an interesting quirk (e.g., searching "car" returns "cardigan" because the letters overlap). I kept this behavior as it highlights the limitations of naive text search versus semantic vector search, but it was an interesting divergence from standard "exact match" expectations!
