## Tools

### Tool 1: search_listings

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Searches the mock listings dataset for items that match a keyword in their title or description, match the exact size, and fall under the maximum price limit.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `description` (str): Keyword or phrase to search for (e.g., "graphic tee").
- `size` (str): Exact size to filter by (e.g., "M", "W30"). Can be `None`.
- `max_price` (float): The maximum allowed price. Can be `None`.

**What it returns:**
<!-- Describe the return value — what fields does a result contain? -->
A list of dictionaries, where each dictionary represents a complete matching listing object containing fields like `id`, `title`, `description`, `category`, `style_tags`, `size`, `condition`, `price`, `colors`, `brand`, and `platform`.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if no listings match? -->
If no items match the criteria, it returns an empty list `[]`. The planning loop will catch this empty list and return an error message asking the user to loosen their search constraints rather than passing empty data to the next tool.

### Tool 2: suggest_outfit

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Sends the newly found clothing item and the user's current wardrobe to the LLM to generate 1–2 paragraphs of styling advice.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `new_item` (dict): A single item dictionary returned by `search_listings`.
- `wardrobe` (dict): The user's wardrobe object containing an `items` array.

**What it returns:**
<!-- Describe the return value -->
A string containing styling advice, explicitly mentioning items from the user's existing wardrobe to pair with the new item.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the wardrobe is empty or no outfit can be suggested? -->
If the wardrobe's `items` list is empty, the tool will not crash. It will fallback to prompting the LLM to provide general styling advice for the `new_item` based purely on its own `style_tags`, `colors`, and `category`.

---

### Tool 3: create_fit_card

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Takes the generated outfit suggestion and item details, and condenses them into a short, punchy, highly shareable social media caption using the LLM.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `outfit` (str): The styling advice generated by `suggest_outfit`.
- `new_item` (dict): The single item dictionary returned by `search_listings` (used to pull in price and platform details).

**What it returns:**
<!-- Describe the return value -->
A short string formatted like an Instagram or TikTok caption (e.g., "just scored this vintage band tee for $22...").

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the outfit data is incomplete? -->
If the `outfit` string is empty or missing, the tool returns a hardcoded error string: `"Error: Could not generate a fit card because the outfit suggestion is missing."` instead of crashing the agent.

## Planning Loop

**How does your agent decide which tool to call next?**
<!-- Describe the logic your planning loop uses. What does it look at? What conditions change its behavior? How does it know when it's done? -->
The agent uses a sequential loop with a critical conditional check.

It first calls `search_listings`.

It evaluates the returned `results`. If `results` is empty (`[]`), it sets an error string in the session and immediately returns the session to the user, halting execution.

If `results` contains items, it stores the top item (`results[0]`) in the session state.

It then unconditionally calls `suggest_outfit` using the stored item.

It then unconditionally calls `create_fit_card` using the output from the outfit suggestion.

---

## State Management

**How does information from one tool get passed to the next?**
<!-- Describe how your agent stores and accesses state within a session. What data is tracked? How is it passed between tool calls? -->
Information is tracked and passed via a central `session` dictionary.

* The output of `search_listings` is stored as `session["selected_item"]`.

* `suggest_outfit` accesses `session["selected_item"]` and the user's wardrobe, returning a string that is stored as `session["outfit_suggestion"]`.

* `create_fit_card` then reads both `session["outfit_suggestion"]` and `session["selected_item"]` to generate the final string, which is stored as `session["fit_card"]`.

## Error Handling

For each tool, describe the specific failure mode you're handling and what the agent does in response.

| Tool | Failure mode | Agent response |
|------|-------------|----------------|
| search_listings | No results match the query | Sets `session["error"] = "No matching listings found. Try adjusting your size or price."` and returns early. |
| suggest_outfit | Wardrobe is empty | Instructs the LLM to generate general style advice based on the item's tags instead of pairing with existing pieces. |
| create_fit_card | Outfit input is missing or incomplete | Returns a descriptive string: `"Error: Could not generate a fit card because the outfit suggestion is missing."` |

## A Complete Interaction (Step by Step)

Write out what a full user interaction looks like from start to finish — tool call by tool call. Use a specific example query.

**Example user query:** "I'm looking for a vintage graphic tee under $30. I mostly wear baggy jeans and chunky sneakers. What's out there and how would I style it?"

**Step 1:**
<!-- What does the agent do first? Which tool is called? With what input? -->
The agent extracts the parameters from the query and calls `search_listings(description="vintage graphic tee", size=None, max_price=30.0)`.

**Step 2:**
<!-- What happens next? What was returned from step 1? What tool is called now? -->
`search_listings` returns a list of matching items. The agent checks if the list is empty. It is not, so it takes the first result (e.g., "Faded Band Tee — $22, Depop") and saves it to `session["selected_item"]`.

**Step 3:**
<!-- Continue until the full interaction is complete -->
The agent calls `suggest_outfit(new_item=session["selected_item"], wardrobe=<user's wardrobe>)`. The LLM processes this and returns a paragraph describing how to pair the tee with the user's baggy jeans and chunky sneakers.

**Step 4:**
The agent stores the paragraph in `session["outfit_suggestion"]`. It then calls `create_fit_card(outfit=session["outfit_suggestion"], new_item=session["selected_item"])`.

**Step 5:**
The LLM generates a short social media caption. The agent stores this in `session["fit_card"]`.

**Final output to user:**
<!-- What does the user actually see at the end? -->
The user sees three populated panels: the selected item details (Title, Price, Platform), a paragraph explaining how to style it with their specific jeans and sneakers, and a final punchy "fit card" caption ready for social media.
